# Ubuntu 主机键鼠卡住：修复及验证交接

本次只修改源码和测试，未配置构建、未编译、未运行测试，也未在 Ubuntu/Windows 双机环境复现。以下是代码中确认存在的阻塞路径；没有现场日志，不能确定用户每次卡住都由同一路径触发。

## 修复内容

1. `src/lib/platform/XWindowsClipboard.cpp`：X11 剪贴板分块传输开始后，原代码会在没有事件时调用阻塞的 `XNextEvent`，使原有超时检查失效。现仅在事件可读时取事件，保留 250 ms 无进展超时，并增加每次请求 2 秒总等待上限；失败时丢弃不完整内容。
2. `src/lib/server/ClientProxy.cpp`：发送关闭消息后调用同步 `flush()`，网络异常时可能一直等待。服务器原有的 5 秒关闭定时器和本机输入恢复都位于它之后，无法执行。现仅将消息加入发送队列，保留原有异步发送和关闭宽限期。
3. `src/lib/base/EventQueue.cpp`：原来只有事件队列空闲才处理定时器。持续鼠标/网络事件可推迟心跳、断线和切屏处理。现让已到期定时器与排队输入交替执行，避免任意一方长期占用队列。
4. `src/lib/platform/XWindowsScreen.cpp`：返回本机时，先释放键鼠占用并提交给 X 服务器，再查询焦点/屏保状态；鼠标捕获失败时也立即提交键盘释放请求。
5. `src/lib/platform/ClipboardPipe.h`、`PortalClipboard.cpp`：Wayland 剪贴板管道原先在 `poll()` 后仍用阻塞式读写，较大写入可能卡住处理输入捕获的回调线程。现使用非阻塞系统读写，限制无进展等待和总等待，支持部分写入，失败时不发布截断内容；写端关闭后才报告完成。
6. `src/lib/platform/PortalInputCapture.cpp`：无法提供剪贴板时明确回复传输失败，避免请求端继续等待。

## 后续编译和验证

- Ubuntu 主机必须更新。公共事件队列也有改动，建议 Windows 副机一并更新。
- 用户描述可能是“Ubuntu on Xorg”，但尚未确认。Ubuntu 终端运行 `echo "$XDG_SESSION_TYPE"`，`x11` 表示 Xorg，`wayland` 表示 Wayland。
- 已补充 `EventQueueTests`（繁忙队列仍执行定时器且不饿死输入）、`ServerTests`（关闭请求不等待对端排空）和 Linux `ClipboardPipeTests`（完整大数据、恰好大小上限、停滞读写、持续少量数据的总超时、超限数据拒绝）。编译后运行这些测试；无显示环境可使用 Qt 的 offscreen 平台，现有 X11 测试需要 X 服务器。
- 双机验证：连续移动鼠标时断开 Windows 网络、Windows 休眠、传大文件期间断网、反复复制大截图并跨屏粘贴，检查 Ubuntu 本机输入能恢复，图片内容完整且文件校验一致。
- X11 专项：模拟剪贴板所有者只发送 INCR 开始通知后停滞，确认记录超时且主循环恢复；持续缓慢发送分块也必须触发总等待上限。

2 秒上限针对一次剪贴板管道/选择请求的等待，不是所有切屏操作的整体耗时保证。异常慢的剪贴板来源可能被取消，需要重新复制；图片编码、X 服务器自身卡住、同步 portal 调用和操作系统问题不在这一等待上限内。
