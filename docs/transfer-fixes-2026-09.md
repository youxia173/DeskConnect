# 大图片与文件传输稳定性修复

## 修复内容

- TLS 写入遇到 WANT_WRITE / WANT_READ 时，保留原始发送缓冲并按需要的方向等待重试，避免在写入重试前执行其他 TLS I/O。依据 [OpenSSL SSL_get_error 文档](https://docs.openssl.org/master/man3/SSL_get_error/)。每次 TLS 写入最多 64 KiB，并检查分配失败。
- 关闭 TLS 连接时先停止网络调度，再获取 SSL 锁，避免与网络线程互相等待。
- Windows 线程取消的两个函数原先重复锁定同一个 `std::mutex`；网络线程退出测试复现了 `resource deadlock would occur` 异常。修复锁范围，并将跨线程引用计数改为原子计数。
- TCP 接收缓存达到约 1 MiB 时暂停接收，消费到低水位后恢复。协议层每轮读取最多 256 KiB，为处理消息和定时器留出机会。
- 连续非空的流缓冲及时回收已经消费的头部，避免内存随累计传输量增长。
- 客户端接收图片时使用服务端下发的剪贴板上限，避免被客户端遗留的服务端设置误拦截。新配置的默认上限为 128 MiB。
- 剪贴板读取和序列化减少重复图片复制；排队中的同一剪贴板只保留最新未发送快照；检查分块的剪贴板编号和序号。
- 校验 Windows 位图头、像素长度，修复 V4/V5 位图色彩掩码偏移；忽略异常或仅限本机使用的网络剪贴板格式，避免非法格式编号越界。
- 文件接收检查开始/结束顺序、64 位长度、累计大小、最终 flush 结果；独占创建接收文件，避免覆盖或误删其他文件；拒绝危险文件名。
- 服务端接收会话绑定来源客户端，避免其他客户端的分块或断线干扰当前传输。新文件清单可替换同一连接上已取消或中断的接收。

## 验证

Windows x64，MSVC 14.44，Qt 6.8.3，OpenSSL 4.0.2，Release 编译。

相关测试套件：`TransferTests`、`ClipboardChunksTests`、`ClipboardTests`、`ServerProxyTests`、`MSWindowsClipboardTests`。

新增覆盖：

- 64 MiB 剪贴板完整分块组装及内容检查；不同序号/编号的分块拒绝。
- 256 MiB 连续流缓冲压力测试，检查内容及已分配容量保持有界。
- 64 MiB 连续协议数据的分批读取与消费者处理。
- TLS 写入重试的读/写事件选择，Windows 网络线程创建与退出。
- 8 MiB 本机 TCP 实际传输：接收暂停、恢复与逐字节一致性。
- 64 MiB 文件接收后的 SHA-256 一致性，零字节文件，5 GiB 长度头（不是实际传输 5 GiB），整数溢出、截断、中断清理、同名文件保留和非法文件名。
- 不完整位图和异常剪贴板格式。

## 使用与剩余验证

两台 Windows 电脑都使用同一份修复版。已有设置不会被自动覆盖：若服务端剪贴板上限仍是旧的 3 或 32 MB，请在服务端配置里调整到 128 MB。截图传输使用的是解码后的位图大小，不能按 PNG 文件大小估算。

已完成本机编译、自动化测试和 TCP 回环验证；尚未在两台真实电脑之间验证实际截图粘贴、数 GiB 文件、双向 TLS 满速传输和断网重连。Linux/macOS 尚未编译或运行验证。本次没有新增断点续传协议，网络真正中断后仍需重新发送。
